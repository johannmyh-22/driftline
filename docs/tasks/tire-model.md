## 背景(读一分钟,不然会做偏)

driftline 是一个 Web 端的写实赛车计时赛。项目正在从「反重力悬浮」改成
「真实车辆」,物理换成 Rapier 引擎 + 四轮 raycast。

**引擎不提供轮胎模型,而赛车手感的绝大部分就在轮胎上。** 引擎负责刚体积分和
碰撞,四个轮子每帧各自算出「这条胎现在能给多大的力」,再把力施加到车身上 ——
你要写的就是中间这个「算力」的函数。

它是纯函数:输入一条胎当前的工作状态,输出这条胎产生的力。不碰 three.js,
不碰 Rapier,不碰渲染,没有任何状态。

## API(签名照抄,不要改)

```ts
/** 一条轮胎某一瞬间的工作状态。全部是接地点的局部量。 */
export interface TireState {
  /**
   * 纵向滑移率 κ。0 = 纯滚动,正 = 驱动打滑,负 = 抱死拖滑。
   * 定义:(轮速 - 车速) / max(|车速|, eps)
   */
  slipRatio: number;
  /** 侧偏角 α(弧度)。轮胎实际前进方向与轮胎指向的夹角。 */
  slipAngle: number;
  /** 垂直载荷(牛),恒为正。由悬挂给出,已经含了载荷转移。 */
  load: number;
  /** 路面附着系数。沥青 1,路肩 0.7,沙地 0.45(具体值由调用方给)。 */
  friction: number;
}

/** 轮胎产生的力(牛),接地点局部坐标。 */
export interface TireForce {
  /** 纵向力,正 = 推着车往前。 */
  longitudinal: number;
  /** 侧向力,正 = 指向轮胎局部 +x。 */
  lateral: number;
}

/**
 * 算一条胎当前产生的力。
 *
 * 结果写进 `out` 并返回它 —— 每帧被调四次,不能在这里分配对象。
 */
export function tireForce(state: TireState, out: TireForce): TireForce;
```

## 要实现的四件事

### 1. Magic Formula(Pacejka '89 简化式)

纵向和侧向各用一条同样形状的曲线:

```
F(s) = D · sin(C · atan(B·s − E·(B·s − atan(B·s))))
```

- `s` 纵向用 `slipRatio`,侧向用 `slipAngle`(弧度)
- `D` = 峰值力 = `μ(load) · load`(见第 2 条)
- `B` `C` `E` 是形状参数,进 `TIRE` 段
- 纵向和侧向的形状参数**要分开两组**,真实轮胎这两条曲线不一样

**曲线过了峰值必须往下掉。** 这是整件事的重点 —— 宪法写着
「过弯要有速度代价,不做怎么开都能拽回来的街机手感」,而「掉下来」正是
打滑失控的物理来源。峰值之后还单调上升的实现是错的。

### 2. 载荷敏感性(**最重要的一条,别漏**)

峰值附着系数随载荷上升而**下降**:

```
μ(Fz) = friction · μ0 · (1 − loadSensitivity · (Fz − Fz0) / Fz0)
```

`Fz0` 是额定载荷(取整车静止时单轮分担的重量)。

**为什么这条最重要:** 四轮模型相对单点模型的全部意义,就在于四个轮子的
载荷会随刹车/过弯转移。如果 μ 与载荷无关,那么「左轮多分 500N、右轮少分 500N」
的总抓地力和平均分配**完全一样**,四个轮子就白算了,刹车点头和过弯侧倾也就
不产生任何操控后果。有了这条,载荷转移才会让总抓地力下降,极限才有意义。

`μ` 要钳到不小于 0 —— 载荷极大时公式会算出负数。

### 3. 摩擦圆(联合滑移)

纵向和侧向共用一份摩擦力预算,不能各拿各的满值。用最简单的那种做法就行:

1. 分别算出纯纵向力 `Fx0` 和纯侧向力 `Fy0`
2. 组合滑移强度 `σ = hypot(slipRatio / peakSlipRatio, slipAngle / peakSlipAngle)`
3. 按 `σ` 把两个力各自缩放,使得合力不超过 `μ(load) · load`

**验收标准是行为,不是公式:** 满油门打滑时侧向力要接近 0(所以直线加速中
猛打方向不该立刻转向),抱死刹车时同理。

### 4. 数值安全

- `load <= 0`(轮子离地)→ 两个分量都返回 0,**不要返回 NaN**
- 输入含 NaN / Inf → 返回 0,不要把 NaN 传下去

**这条不是形式主义。** 这个项目被 NaN 坑过两次整屏黑屏,原因都是
「一个 NaN 被后面的环节摊到一大片」。轮胎力会进刚体积分,一帧 NaN 会让
车的位置永久变成 NaN,画面直接消失,而且**关掉某个效果排查会给出错误结论**
(`0 * NaN` 还是 NaN)。详见 `docs/HANDOFF.md` 第五节第 6 条。

## 数值目标(写实,不是街机)

整车参考值,用来定 `TIRE` 段里的数:

| 项目 | 值 |
|---|---|
| 整车质量 | 1200 kg |
| 单轮额定载荷 `Fz0` | 1200 × 9.81 / 4 ≈ 2943 N |
| 干沥青峰值附着 `μ0` | 1.4(赛车光头胎的量级) |
| 峰值侧向加速度目标 | **1.3 ~ 1.6 g** |
| 峰值出现的滑移率 | 0.10 ~ 0.15 |
| 峰值出现的侧偏角 | 6° ~ 10° |
| 载荷敏感系数 | 0.15 左右(即载荷翻倍,μ 掉约 15%) |

**注意别照抄现在的数值。** 现有的悬浮载具峰值侧向加速度是 3.80 g,
那是反重力设定下的数,真车做不到,照抄会直接把写实方向做没。

## 测试要求(`tests/unit/tire.test.ts`)

这个项目在测试上吃过一次大亏,务必读完再写:

> 转向左右反了。单测断言的是「yaw 与 steer 同号」,而 yaw 正方向到底是左是右
> *正是搞反的那件事* —— 断言和 bug 共用同一个错误前提,83 条测试全绿也拦不住。
> **教训:断言物理量,不要断言内部约定。**

所以下面每一条断言的都是**可观测的物理行为**,不是「某个中间变量等于某个值」。
至少覆盖这些:

1. **零滑移零力。** `slipRatio = 0, slipAngle = 0` → 两个分量都是 0。
2. **峰值位置。** 扫描 `slipRatio` 从 0 到 1,峰值落在 `TIRE` 里标称的峰值滑移率
   附近(±0.05)。侧偏角同理。
3. **过峰下降。** 峰值之后的力**严格小于**峰值。扫一遍断言单调性,
   不要只测一个点。
4. **峰值量级对得上。** 额定载荷、`friction = 1` 时,峰值侧向力 / (质量/4 × g)
   落在 1.3 ~ 1.6 g 区间。
5. **载荷敏感性。** 载荷翻倍时,峰值力**小于**翻倍。这条要显式断言,
   它是四轮模型成立的前提。
6. **摩擦圆。** 纵向拉到远超峰值滑移时,同一时刻的侧向力显著小于纯侧向工况
   (给个具体倍数,比如小于 20%)。
7. **符号对称。** 滑移取负,力也取负,大小相等。
8. **路面。** `friction = 0.45` 时的峰值力约为 `friction = 1` 的 45%(容差放宽些)。
9. **不返回 NaN。** `load = 0`、`load` 为负、滑移为 `NaN` / `Infinity`,
   四种输入都要断言输出是有限数。
10. **不分配。** 同一个 `out` 对象连调两次,断言第二次的返回值 `toBe` 那个 out
    对象本身(引用相等)。

### 一条重要的自查

写完之后,**故意把实现改坏一次,确认测试真的会红**。比如:

- 把载荷敏感系数改成 0 → 第 5 条必须失败
- 把 Magic Formula 换成一条不封顶的直线 → 第 3 条必须失败

如果改坏了测试还是绿的,说明那条断言是空的,要重写。这个项目已经在
「测试全绿但功能是坏的」上栽过两次。

**测试失败时先找真实原因,不要放宽容差。** 放宽容差会把真实原因永久盖掉 ——
这条也是踩出来的。
