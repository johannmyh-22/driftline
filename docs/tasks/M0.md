# M0 — 骨架与验证回路

> 这是给云端 session 的任务描述。先读根目录 `CLAUDE.md`,再读 `docs/PLAN.md` 的 M0 段。

## 为什么这个里程碑重要

你(agent)在 CI 环境里没有 GPU、没有显示器。M0 的唯一目的,是先建立一条**你能自己看到渲染结果**的回路。
在这条回路成立之前,不要写任何玩法代码 —— 否则后面每一次改动你都只能靠"编译通过"来猜画面对不对。

## 交付清单

### 1. 工程骨架

- Vite + TypeScript,`tsconfig.json` 开 `strict: true`
- `vite.config.ts` 设 `base: '/driftline/'`(Pages project site 需要)
- three.js 最新稳定版
- `package.json` scripts 必须齐全,名字与 `CLAUDE.md` 一致:
  `dev` / `typecheck` / `build` / `test` / `test:visual` / `shoot`
- 目录:`src/core/` `src/game/` `src/gfx/` `src/audio/` `scripts/` `tests/`

### 2. 固定步长主循环 `src/core/loop.ts`

累加器模式,固定 `dt = 1/60`,渲染做插值。必须支持两种驱动:

- **实时模式**:`requestAnimationFrame` 驱动,带最大追帧数上限(防止切回标签页后一次追上千帧)
- **测试模式**:完全不注册 rAF,只能由外部调用 `advance(frames)` 推进

### 3. 确定性随机 `src/core/rng.ts`

mulberry32 或 xorshift128。导出一个可注入的 `Rng` 类。
加一条 ESLint 规则或 CI grep 检查,**禁止 `src/` 下出现 `Math.random()`**。

### 4. 测试接口

`?test=1&seed=N` 时挂载:

```ts
window.__DRIFTLINE_TEST__ = {
  ready: Promise<void>,
  advance(frames: number): void,
  setCamera(preset: string): void,
  snapshot(): Record<string, number>
}
```

`snapshot()` 在 M0 阶段返回 `{ frame, elapsed, spinnerRotation }` 即可,后续里程碑往里加字段。

### 5. 占位场景(**只是管线验证,不是游戏内容**)

- 一个 flat-shaded 多面体(icosahedron / 手写 BufferGeometry),随帧数确定性旋转
- 程序化渐变天空盒(shader,不用贴图)
- 地面网格,颜色由 seed 决定
- 定向光 + 半球光,能看出明确的明暗面

保持简单。M1 会把它整个删掉。

### 6. 截图脚手架 `scripts/shoot.ts`

Playwright 驱动 chromium,`npm run shoot` 可带参数(seed、机位、帧数),输出 PNG 到 `tests/visual/__output__/`。

`playwright.config.ts` 的启动参数(**这几个 flag 缺一个 WebGL 就拿不到 context**):

```ts
launchOptions: {
  args: [
    '--use-gl=angle',
    '--use-angle=swiftshader',
    '--enable-unsafe-swiftshader',
    '--disable-lcd-text',
  ],
},
viewport: { width: 1280, height: 720 },
deviceScaleFactor: 1,
```

流程:起 preview server → 打开 `?test=1&seed=42` → `await ready` → `advance(120)` → 截图。
**不要用 `waitForTimeout` 等渲染**,等 `ready` 和显式 `advance`,否则截图不可复现。

### 7. 冒烟测试 `tests/visual/smoke.spec.ts`

- **非黑屏**:采样像素,方差高于阈值(纯色画面说明渲染挂了)
- **无 console error**,无 uncaught rejection
- **状态推进**:`advance(60)` 前后 `snapshot().frame` 差值恰好为 60
- **确定性**:同 seed 跑两次,`snapshot()` 数值完全一致

不做像素级截图比对。

### 8. CI 与部署

`.github/workflows/ci.yml` 和 `deploy.yml` 已在仓库里,**不要改动它们的结构**。
你的任务是让工程满足它们的假设(script 名称、`dist` 输出目录、截图输出路径)。

## 完成标准

- [ ] `npm run typecheck` / `test` / `build` / `test:visual` 本地全过
- [ ] `npm run shoot` 产出截图,**你用 Read 工具读过这张图,确认看到了受光的旋转多面体和渐变天空**
- [ ] CI 全绿
- [ ] Pages 线上可访问
- [ ] PR 描述里贴上 Pages 链接和截图,说明"M0 验证回路已成立"

## 边界

不要做:载具、赛道、物理、音频、HUD、菜单、后处理。这些分别属于 M1–M5。
如果你觉得某个后续里程碑的东西"顺手就能做",也不要做 —— 那会让这个 PR 变得无法审查。
