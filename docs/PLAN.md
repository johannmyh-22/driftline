# driftline 路线图

每个里程碑 = 一个 PR。合进 `main` 自动部署到 Pages,人类在真机验收后才开下一个。

---

## M0 — 骨架与验证回路

**目标:让"云端 agent 能看见自己的画面"这件事先成立。**

- Vite + TypeScript(strict) + three.js 工程
- `src/core/loop.ts`:fixed timestep 累加器,渲染插值
- `src/core/rng.ts`:seeded PRNG(mulberry32 或 xorshift128),全局禁用 `Math.random()`
- `?test=1&seed=N` 测试模式 + `window.__DRIFTLINE_TEST__` 接口(契约见 CLAUDE.md)
- 场景内容:一个受光的旋转多面体 + 渐变天空 + 地面网格。**仅用于验证管线,不是游戏内容**
- `scripts/shoot.ts`:Playwright 无头截图,SwiftShader 参数,输出到 `tests/visual/__output__/`
- `tests/visual/smoke.spec.ts`:非黑屏(像素方差 > 阈值)、无 console error、`advance(60)` 后状态推进
- CI workflow + Pages 部署 workflow

**验收:** Pages 线上能打开看到画面;CI 全绿;`npm run shoot` 产出的截图我能读出内容。

## M1 — 手感

**目标:一辆开起来就爽的悬浮载具。只做手感,不做内容。**

- 输入层(键盘 + 后续可扩展手柄/触屏),支持录制输入帧序列
- 悬浮控制器:向下 raycast 求离地距离 → 弹簧阻尼维持悬浮高度;贴合地面法线做姿态对齐
- 推力 / 阻力 / 侧向摩擦 / 空气刹 / 转向响应曲线,全部参数进 `src/game/tuning.ts`
- 跟随相机:位置弹簧 + 速度相关 FOV 拉伸 + 轻微 roll
- 一块足够大的平地 + 几个障碍物

**验收(需人类试玩):** 加速、转向、擦地、脱离地面再落回的手感。反馈请给具体数值方向。

## M2 — 赛道生成

- Catmull-Rom 闭合 spline → 沿弧长重采样 → 生成带侧倾(banking)的赛道条带网格
- 侧倾由曲率推导;护栏 / 路肩 / 起跑线
- **生成后校验**:自交检测、最小曲率半径、最大坡度,不合格则换 seed 重采样
- 检查点系统 + 圈计时 + 出界重置到最近检查点
- 赛道外的 simplex noise 地形,按高度/坡度上顶点色

**验收:** 连续 10 个随机 seed 都能生成出可跑完的赛道。

## M3 — 视觉基线(写实)

**目标:尽量接近实拍照片。** 方向由人类在 2026-08 改定,原「低多边形」作废,
理由与天花板见 `CLAUDE.md` 的「视觉方向」一节。

- 材质:PBR。沥青 / 混凝土 / 岩石的 albedo、法线、粗糙度全部运行时程序化生成
  到 `DataTexture`,零素材文件
- 光照:物理光照单位 + 定向光阴影(级联)+ **程序化生成的环境贴图做 IBL**,
  这是拉近真实感最有效的一步
- 天空:Rayleigh / Mie 大气散射,不是渐变色卡
- 后处理:ACES 色调映射 → AO → bloom → SMAA → 轻度暗角与色差
- 速度感:~~动态模糊或速度线~~ **已完成(2026-08,见 HANDOFF 第五十二节)**:
  `gfx/motionBlur.ts`,径向动态模糊,中心取**速度方向在画面上的投影**(扩张
  焦点)而不是屏幕中心。尾焰、地面掠影早已完成。
- 三套主题(时段 / 天气),由 seed 决定

**验收(需人类看图):** 附 3 张不同赛道的截图 + Pages 链接。

**性能风险:** 重后处理 + 阴影 + 加密网格会拖慢 SwiftShader 的截图回路,
而那条回路是整个项目的地基。做的过程中要持续量,超预算必须先解决。

## M4 — 游戏循环

- 开始菜单 / 暂停 / 重开 / seed 输入框

## M5 — 内容与音频

- 3–5 条精选 seed 赛道,各配主题与目标时间
- 程序化音频:引擎音(锯齿波 + 随车速调制的低通滤波)、气流噪声、撞击包络、UI 音
- 主音量与静音,尊重 `prefers-reduced-motion`

**已从范围删除(2026-08,由人类拍板):** 加速带、跳台、隧道段。跳台和加速带
是拉力赛/越野赛的元素,正经赛道(参照的纽博格林北环)不会有,和「现实参照」
这条主线直接冲突;隧道虽然有真实依据(摩纳哥大奖赛),但人类要求三样一起
砍掉,不做取舍,理由与讨论见 `docs/HANDOFF.md` 第三十一节。

## M6 — 移动端与性能

- ~~触屏控制(虚拟摇杆或倾斜)~~ **已完成(2026-08,见 HANDOFF 第五十节)**:
  `core/touchInput.ts`(纯判据,可单测)+ `game/touchOverlay.ts`(DOM 控件)。
  左半屏相对摇杆 + 油门/刹车/倒车三个圆钮,布局在 `TOUCH`。选了摇杆不是倾斜:
  倾斜没法同时表达"回正"和"握持角度",而且校准问题无解。
- ~~DPR 自适应、动态分辨率缩放、低配自动关后处理~~ **已完成(2026-08,见
  HANDOFF 第四十八节)**:`src/core/perfGovernor.ts` + `PERF`(tuning)。判据是
  「实测帧间隔相对**学出来的**显示器周期」,不是绝对毫秒 —— 绝对阈值在
  144 Hz 屏上永不降档、在 30 Hz 屏上一路降到底。五档阶梯先降分辨率、最后
  一档才关后处理;`?quality=N` 可以手动钉死一档。SwiftShader 上实测最低档
  比最高档快 **2.8 倍**(1687 → 604 ms/帧)。
- 首屏加载 < 3s,中端手机稳定 60fps

  **量出来了,而且离目标还差得远 —— 剩下的差距几乎全是物理引擎。**
  `npm run loadtime`(2026-08 新增,CDP 限速 + Resource Timing 实测):

  | 网络 | 可开始画 | 开画前传输 |
  |---|---|---|
  | 不限速 | 1381 ms | 1.27 MB |
  | 4G | 2536 ms | 1.27 MB |
  | 慢 4G | 4164 ms | 1.27 MB |
  | **3G** | **8556 ms** | 1.27 MB |

  首屏 JS 的构成(gzip):**Rapier 的 wasm 1023 KB,其余(three.js + 全部
  游戏代码)277 KB —— 物理引擎占 79%。** 把它拿掉的话 3G 上大约 1.4 秒就能
  开画,目标轻松达成;不拿掉的话再怎么优化剩下那 277 KB 也没有意义。

  **接下来怎么办是需要人类拍板的取舍**,三条路(见 HANDOFF 第五十一节):

  1. 接受现状,把 M6 这条目标改写成「4G 进 3 秒」(现在 2536 ms,已经达成)。
  2. 换回独立 `.wasm` 的包(小 288 KB)。**CLAUDE.md 里已经否过一次**,理由是
     它在 vitest 里 import 不起来,而「测的和跑的是同一个二进制」是这个项目
     整套测试的前提。要改就是改那条前提,不该我自己动。
  3. 让首屏**不等物理**:世界/赛道/天空的渲染本来就不需要 Rapier,可以先把
     场景画出来、车晚一点进场(和车辆模型那次是同一个套路)。收益最大,但要
     动 `World` 的构造流程,而且玩家会看到几秒「有赛道没有车」的画面 ——
     这是个产品决定,不是纯技术决定。

- Lighthouse 检查

## M7 — AI 对手(竞技赛制,草案,2026-08 由人类要求)

**目标:从"一个人对着自己最佳圈跑"变成"同场多辆 AI 车实时竞速"。** 会超车/
被超车/碰撞,按名次而不是纯粹比圈速。详细取舍见 `docs/CLAUDE.md`「现实参照」
一节末尾和 `docs/HANDOFF.md` 对应章节。这一节只是架构草案,体量接近一个完整
里程碑(参考 M2/M4 各自花了好几轮才做完),**还没有开始实现**。

- ~~**载具间碰撞**~~ **已完成(2026-08,见 HANDOFF 第三十六、三十七节)。**
  下面是当初的设计草案,留作背景。原文:`Physics.createChassis()` 现在明确不挂碰撞体(接地靠
  `Course.sample()` raycast,那条不变量管的是**地面**查询)。车与车碰撞是
  新增能力,不冲突这条约定,但要求所有参赛车共享**同一个** `Physics` 世界——
  这和 `Ghost`(第二十六节,独立 `Physics` 世界,靠隔离避免 `Vehicle.update()`
  内部的 `physics.step()` 把世界重复推进)的方案正好相反。大概率要把
  `physics.step()` 从 `Vehicle.update()` 里搬出来,变成 `World` 每帧显式调
  一次:所有车先把各自的力/力矩都上好,再统一 `step()` 一次。这是整个子系统
  里最容易出错、必须优先设计对的一块。
- ~~**AI 竞速逻辑**~~ **已完成(2026-08,见 HANDOFF 第四十一节)**:新增
  `src/game/racingPilot.ts`。`Autopilot` 原样保留当验收工具。实测单圈从
  「比目标慢 56~74%」变成「快 6~23%」,默认难度系数压到 0.7 让它落在目标
  时间附近(±10%),全程 0 撞墙。
- ~~**赛制**~~ **已完成(2026-08,见 HANDOFF 第四十二节)**:
  `src/game/raceSession.ts`。3 圈制、3 秒发车倒计时(期间输入锁死)、
  冲线记名次与用时、冠军冲线后 20 秒宽限强制结算(没冲线的记 DNF)、
  HUD 结算面板。
- ~~**HUD**:加名次显示(如 P3/6)、和前车的差距。~~ **已完成(2026-08,见
  HANDOFF 第四十节)**:`src/game/standings.ts` + HUD 的 `P几/几` 与 GAP 行。

**M7 四格全部完成(2026-08)。** 碰撞、AI 竞速逻辑、赛制、HUD 名次都已落地,
等人类验收。

**2026-08 由人类拍板全部加入并已完成**(原本列为「范围决策」的那批):
多辆对手车(3 辆 + 发车格)、尾流/牵引、轮胎磨损、刹车热衰、碰撞损伤、
物理层变速箱。见 `docs/HANDOFF.md` 第四十三节。

仍然没做、也仍然是范围决策的:燃油载荷、天气/路面温度、可修复的维修进站。
逐条现实差距对照见第四十一节。
